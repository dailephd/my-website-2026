Current website scope

- Main routes: `/`, `/work`, `/products`, `/products/my-dev-kit`, `/writing`, `/about`, `/contact`
- Local content source: `src/content`
- Roadmap source: `src/content/roadmaps.ts`
- Product-family story:
  - `my-dev-kit` = static repository/codebase evidence
  - `my-dev-kit-orchestrator` = workflow and lifecycle control
  - `my-frontend-observer` = rendered browser/runtime evidence
  - `my-dev-kit-lab` = optional assurance and evaluation
  - present them together as `my-dev-kit Ecosystem`
  - an external human or coding agent edits source; Orchestrator does not automatically run agents or tools; Observer never edits source; Lab is not mandatory for every edit
  - `ProductArchitectureVisual` owns the hybrid workflow, Observer correction loop, and optional Lab assurance lane

Diagram rules

- Before diagram work, read `docs/DESIGN.md` and `docs/DIAGRAM_DESIGN.md`.
- Use `src/styles/diagrams.css` and the shared primitives in `src/components/diagrams/` when the semantic role matches.
- Keep diagram-specific topology local; do not recreate canvas/node/connector styling independently.

Content and design rules

- Use `docs/`, not `doc/`.
- Keep website-owned content in `src/content`.
- Use `src/lib/content` for adapters and validation.
- Do not hardcode structured content directly in page components.
- Use semantic HTML, keyboard access, visible focus states, and reduced-motion-safe behavior.
- Render roadmap status as text, not color alone.
- Design target:
  - premium independent product lab
  - big-company polish
  - personal technical founder ownership
  - soft grey light mode, not pure white
  - charcoal grey dark mode, not pure black
  - violet/cyan accents
  - solid premium cards
  - restrained glow
  - clean typography
- Avoid heavy animation, WebGL, particle engines, and cursor gimmicks in v1.
